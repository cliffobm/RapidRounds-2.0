# Direct tester access

The review branch provides `/tester-login` for the existing email/password accounts in the isolated RapidRounds test Auth project. Passwords are entered directly in the app and are not stored in source, configuration or review notes. Password login uses the shared Supabase SSR cookie client. Successful sign-in performs a full document navigation to Home or a validated local deep link; sign-out also reloads the document to discard the client router cache.

The review deployment requires both a freshly server-verified nonanonymous user and membership in the organizer's server-only `RR_TESTER_USER_IDS` list. The initial list contains the six confirmed, nondeleted, nonanonymous accounts already provisioned in the test project. No users, passwords, database tables, Auth settings or production services were changed. New public signups do not gain tester access. To invite another colleague, provision their test account privately, confirm it, and explicitly add its Auth UUID to this review branch's allowlist before redeploying. Never put the list or a service-role key in `NEXT_PUBLIC_` configuration.

`RR_REQUIRE_TESTER_LOGIN=true` is scoped to Preview and `feature/cjis-foundation` in the separate Vercel review project. The stable tester hostname also enforces the gate if that flag is accidentally removed. A missing or empty allowlist fails closed. Other explicitly offline builds retain the ungated learning workflow used by regression tests.

Middleware covers all routes, including future pages, unknown paths, RSC and prefetch requests. Only exact authentication entries, necessary logo resources and Next static assets are public. There is no general filename-extension exception or broad `/_next/` exception. The public image optimizer accepts only the exact logo assets. Pages Router JSON data requests are disabled in this App Router review app. Unsafe requests to public login pages are rejected. Unauthenticated protected-page mutations return JSON 401 rather than replaying a POST through a login redirect.

All inherited review `/api/*` endpoints are disabled before their handlers execute. They are not required for password Auth, which goes directly to Supabase Auth. This prevents review traffic from invoking legacy database, payment, AI or metrics operations. Identity rejection, refresh, outages and redirects preserve Auth cookie updates and return private/no-store headers. Review responses carry noindex headers; authenticated pages are dynamically rendered. This route gate is not database RLS and does not encrypt public client JavaScript bundles or make the client-side question bank suitable for confidential content.

Vercel's login requirement is removed only from the stable tester alias after the deployed app gate is checked under authorized preview access. The project-wide deployment protection remains enabled, including older immutable deployments. This is a preview access change, not a production promotion. Before pointing the public alias at a different application or rollback without this gate, remove its deployment-protection exception first.

Verification includes mocked positive Auth/cookie/allowlist tests, failed/anonymous/forged-session checks, safe redirects, cookie refresh/error paths and separate browser tests for the gated and offline workflows. Live negative Auth and unauthenticated access can be checked without knowing a tester password. A fresh positive login using the dedicated URL requires the reviewer to enter their existing credentials privately; no live positive result should be claimed until that happens. Prior positive login persistence and logout were reported by the user on the earlier Account flow.

Progress remains browser-local and shared between accounts in the same browser profile. Signing in does not create per-account or cross-device learning history. Use separate profiles on shared devices.
